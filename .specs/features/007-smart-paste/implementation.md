## Native observations and boundaries

- Read [the AX adapter receipt](evidence/native-ax-adapter.json): the production `MacAxTextPort` verified an astral-character replacement, skipped a 1,000,001-unit field and a password field, and detected a write applied 151 ms after the window (guard `AppliedLate`). A cold first AX contact with a freshly launched app may exceed the 100 ms preparation budget and then only skips.
- Read [the pasteboard adapter receipt](evidence/native-pasteboard-adapter.json) (fix round 1, HEAD `b499073`): the helper binary and the test executable are hashed during the run and the helper is checked for protocol version 2 before any scenario. On a named pasteboard, rich multi-item content round-tripped byte for byte through the real helper (under load the derived UTF-16 text is the only type that can miss the deadline; AppKit re-derives it), publication and restoration prepared the pasteboard with `currentHostOnly` (`prepare(1)`, recorded at the AppKit call because AppKit has no getter), private materialization is current-host-only and marked while copy-mode materialization is ordinary plain text, a synthetic concealed copy is withheld without bytes, an armed helper captured in about 10 ms, 10,003 items were truncated to 10,000 with 3 counted, a newer copy was never overwritten, an empty pasteboard came back empty, a 1 s blocking promise was cut at about 200 ms keeping completed types, and the byte budget skipped by name. AppKit served the second external read from its cache without a callback.
- Read [the keyboard receipt](evidence/native-keyboard-adapter.json): French layout → decision `TryAbcThenUs`, Cmd+V key code 9; nothing selected or posted.

- Targeted native Cargo fixture: one ignored opt-in integration test executed and passed. The Cargo application build compiled the real Apple Intelligence bridge; the fixture exercises Swift/AppKit and does not test Apple Intelligence inference. No general clipboard or user focus was touched.
- Read [the provider evidence](evidence/native-spike.json): AppKit cached fulfilled text. A pre-key read suppressed a subsequent provider callback, and two post-key readers produced one callback. Callback-controlled mechanics work; quiet timing after every actual consumer read is not certified. A callback is not an authenticated destination acknowledgement.
- Read [the AX evidence](evidence/native-ax-spike.json): synthetic AXSelectedText replacement and UTF-16 length guard were observed. Requested 20 ms messaging timeouts had measured scheduling overhead; no universal wall-clock timeout or total 250 ms native guarantee is claimed.
- Read [the TIS evidence](evidence/native-keyboard-spike.json): French source resolves Command-V to keycode 9. ABC, US and Dvorak are installed but disabled; this run does not enable layouts or change system configuration.

## Rollout gates

Two Cargo features, both closed by default: `smart-paste-dispatch` (007, [`DICTATION_DISPATCH_WIRED`](../../../src-tauri/src/smart_paste/setting_policy.rs)) and `destination-return` (006, `destination::rollout`). Smart paste is active only on macOS with its gate open (`Rollout { macos, dispatch_wired }`); the route of a dictation is [`insertion_route`](../../../src-tauri/src/smart_paste/dispatch.rs) (smart paste active and configured, 006 session or not).

| `smart-paste-dispatch` | `destination-return` | Settings | Dictation |
|---|---|---|---|
| closed | closed | `smart_paste` refused (`validation_failed`, reason `smart_paste_unavailable`, exit 2, dry runs too), Cmd+V default, no migration (marker 0), beta reliable paste kept, `is_smart_paste_available` false | Identical to `dev`: no actor, no exit hold, the classic method on the main thread (`paste_as_before`) |
| closed | open | As above; `return_to_dictation_app` accepted (006) | Identical to `dev` with 006 open: 006's orchestrator and its main-thread method; no actor |
| open | closed | Smart paste selectable, macOS default, Cmd+V (beta on or off) migrated once with marker 1, beta refused on macOS | No 006 session, so 007 inserts into the application in front: `insert_at_foreground` reads it live through 006's workspace port (`frontmost_now`, the source of 006's guard), names no target when Handy is in front or the foreground is unreadable (AX skipped), and registers a `ForegroundCheck` (not cancelled, same process in front) consulted before the AX write and before the keystroke; local generations start at 2^63. No `insertion-outcome` event (006 publishes none in this state); failures show the existing `paste-error` toast |
| open | open | Both | 006 activates the destination; smart paste is 006's `InsertionPort`: the first `guard.check()` builds the context (`DestinationContext::from_session`, `Insert` set by 006), the actor runs with a `SessionCheck` (006's recheck plus the same process in front, no retargeting), and the outcome becomes `MethodResult::Detailed` (`method_outcome`, `transaction_id`), so failures become `Recover` with the transcript retained and the `paste-error` toast |

On Windows and Linux smart paste is inactive in every state. Opening `smart-paste-dispatch` alone is coherent: smart paste needs a process, a bundle and a generation, which 006's frontmost-at-the-end route gives from the live foreground, and 007 reads that same source itself without a session; it does not depend on 006's activation, which waits for its own native proof and Penflow UI. Opening `destination-return` alone leaves smart paste unselectable. Tested by `each_gate_combination_has_one_route` and the full suite in the four states.

Common to both open routes:

- The actor is started at setup ([app](../../../src-tauri/src/smart_paste/app.rs), [macos_ports](../../../src-tauri/src/smart_paste/macos_ports.rs)): general pasteboard, snapshot helper of the running executable, production AX, keyboard and input-source ports. No pasteboard access or helper process before the first insertion.
- Normal exit: `RunEvent::ExitRequested` holds the first exit, shuts the actor down from a worker with `shutdown_allowance(paste_delay)` (an insertion in progress finishes, the pending transaction settles: restored only after quiet or cap, otherwise the transcript stays as private eager text), then exits again ([exit_gate](../../../src-tauri/src/smart_paste/exit_gate.rs)). A restart is never held; dropping the actor still settles without waiting.
- Enter (009 hook): the legacy `auto_submit` setting is applied once, only after `inserted_verified`, `read_observed` or `typed`, and with a session only when `claim_enter` grants it; never after `clipboard_handed_over` or a failure. 009 replaces this rule.
- Recovery (010 hook): `smart-paste-late-read` carries `PasteDiagnostic {dictation_id, transaction_id, late_read_observed}` (identifiers only); `InsertionOutcome.transaction_id` is the same transaction as a decimal string and `dictation_id` is 006's. In copy mode no diagnostic exists (known limitation).
- Screen Sharing: `smart-paste-hand-over` (identifiers only) shows the translated message "Text placed on the clipboard for the remote screen" on the recording indicator for at least 4 s, the window held up after the hide (`src/overlay/use-overlay-notices.ts`, UI pass `69a6ee73`); with the overlay style none it falls back to the settings-window toast (`src/hooks/use-overlay-none-notices.ts`, which replaces `use-smart-paste-hand-over.ts`). With `smart-paste-dispatch` closed the event is never emitted and nothing is shown.
- The legacy auto-submit block and `paste_delay_after_ms` of `clipboard::paste` are not used by smart paste.
- Migration placement (unchanged): `settings::apply_settings_migrations` → `setting_policy::migrate`; read-only reads normalize in memory without writing. The first startup after upgrading writes `smart_paste_migration_version` once in both states.

Opening for release: the native acceptance below with Julien, then a separate change that turns `smart-paste-dispatch` on by default; the checked 008 schema is the closed state (its test strips `smart_paste` when the gate is open).

## Native acceptance procedure (AC-016) with Julien

Not run by the agent: it needs real dictation into real applications, enabled layouts (a system settings change), key posting and the general clipboard. Nothing here is claimed passed. Results go to `evidence/native-compatibility.md` (table below) and `evidence/native-compatibility.json`.

Preparation (once):

1. Build the gate-open app from this worktree: `CARGO_TARGET_DIR=/Users/julienm/projects/handy-wt/.target-007 bun run tauri build --features smart-paste-dispatch` (add `,destination-return` only for the combined pass, after 006's own native proof). Record `shasum -a 256 /Users/julienm/projects/handy-wt/.target-007/release/bundle/macos/Handy.app/Contents/MacOS/handy`, the macOS version and the commit.
2. Install that Handy.app, grant it Accessibility (System Settings › Privacy & Security › Accessibility), relaunch it.
3. Check the method and the log level: `handy settings output get paste_method --json` must show `smart_paste` (migration) — otherwise `handy settings output set paste_method smart_paste --json`; keep `clipboard_handling` at `dont_modify`; `handy settings set log_level debug --json`. Each dictation logs `[smart-paste] dictation N: <Kind> via <Path>` in `~/Library/Logs/com.pais.handy/handy.log` (no text).
4. Enable the layouts French AZERTY, ABC (or U.S.) and Dvorak in System Settings › Keyboard › Input Sources (Julien's decision: this changes system settings).
