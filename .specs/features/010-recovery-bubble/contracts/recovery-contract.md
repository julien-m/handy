# Recovery Bubble Local Contract

Inspect [the technical plan](../plan.md) for decision, reason, threading, testing and dependency context. Local Tauri/native commands and a settings descriptor only; no HTTP endpoint/OpenAPI.

| Boundary | Contract |
|---|---|
| Rollout gate | Behind 006's `destination-return` Cargo feature (`destination::rollout`). Closed (default build): no session, `dev`'s `paste-error` on failure (Linux and 007's sessionless path included), no bubble, `RecoveryPort`, classification or setting (`not_found`/4, checked schema unchanged). Open: this contract |
| 006 input | `InsertionOutcome` as delivered in `destination/outcome.rs`: `dictation_id`, `destination_generation`, `outcome_id`, `target`, `destination_source`, `status`, `method_outcome`, `transaction_id`, `reason`, `history_status`, `history_entry_id`, `transcript_ref`, `completed_at`; opaque `transcript_ref` resolved by the trusted native manager; dedupe by `outcome_id`, stale identity discarded |
| Recovery instance | Native immutable full text, copied from 006's slot before anything else; unique bubble_id plus dictation_id/destination_generation/transaction_id (006's decimal `String`), phase (`Presenting`, `Visible`, `Dragging`, `Copying`, `Closed`), `BubbleReason` (`AppClosed`, `PinnedAppNotRunning`, `ActivationFailed`, `InsertionFailed`, `NoTextField`; distinct from 006's `context::RecoveryReason`), target name (session snapshot, then `WorkspacePort::instances`, then the localized noun), history_status and late-read flag; no public verified flag |
| No-text-field reason | 010's `Recover(NoTextField)` verdict reaches 010 as a typed reason, never a generic failure: 006 is extended so `GuardRefusal::RecoverInstead(RecoveryReason)` keeps the verdict reason, `outcome::DestinationFailure` gains `NoTextField` (wire `no_text_field`) and `insertion::refusal_report` maps one to the other; no correlation record; a reason decided before insertion never shows the partial-insertion detail |
| Surface snapshot | Targeted preview/reason/history metadata, current bubble identity, actions/capabilities; no full text app-wide broadcast |
| Action | Copy/Close/explanation/drag request with exact current bubble identity; stale closed instance rejected, never affects successor |
| 007 method outcome | No separate adapter: `InsertionOutcome.method_outcome` carries 007's `PasteOutcome.kind` wire value (`inserted_verified`, `read_observed`, `not_read`, `permission_missing`, `uncertain`, `typed`, `clipboard_handed_over`, `insertion_failed`); only `inserted_verified` is field-verified; 006 waits for the terminal read/no-read result before producing the outcome |
| 007 late read | `PasteDiagnostic { dictation_id, transaction_id, late_read_observed }` after `not_read`, received through `smart_paste::app::FanOutDiagnostics`, which forwards each diagnostic unchanged to `EventDiagnostics` and to 010's native sink; matched with `transaction_id.0.to_string()`. A diagnostic received before the matching outcome is admitted waits in a one-entry buffer keyed by `(dictation_id, transaction_id)`, cleared at the next dictation, and applies to the admitted instance even before it is visible; it updates the matching bubble in place (none in copy-to-clipboard mode, 007 limitation) ("may have been pasted after all"); no second bubble, no outcome, disposition or Enter change; stale or repeated diagnostics ignored |
| 007 AX chain | 007 tries AXSelectedText and compares reread with expected replacement before clipboard (outside special-app strategies); unchanged permits fallback, unexpected change → uncertain with no fallback; 010 never retries insertion; current 007 direct AX budget ≤250 ms including ≤150 ms readback, separate from 010 classification; 007 owns destination-PID guard and clipboard handling |
| 007 restoration | macOS smart paste owns read-confirmed restore: 300 ms quiet after LAST post-Cmd+V read (Jump 1.5 s), capped 8 s after FIRST read; no read under 800 ms (Jump 3 s) → not read, NEVER restore for this dictation including late read/quit/new output; inside 007's actor check publication changeCount and write without interleaving deliberate Copy; changed count abandons restoration, no window cancellation API |
| Deliberate Copy | Async command, write on a blocking worker, never the main thread. With 007's actor running (macOS, `smart-paste-dispatch` active, `SmartPasteRuntime` managed): 010 adds `ActorMessage::DeliberateCopy` behind `SmartPasteActor::deliberate_copy(text)`, written with `PasteboardPort::write_plain_text` (unmarked plain text), serialized with insertions, reads, restoration and timers, reply awaited at most `shutdown_allowance(paste_delay)`; success changes changeCount even for identical text, so pending smart paste restore abandons. Without the actor (macOS `destination-return` only, Windows, Linux): `clipboard::write_text_to_clipboard`, the "copy to clipboard" write of `dev`. Success closes the matching instance. Failure (write error, stopped actor, expired wait): bubble stays open and unchanged with its other actions, logged without text, no dedicated message; original restore guard remains authoritative. Close or a new dictation during Copy closes at once; the write completion is ignored by identity |
| Drag | macOS native plain-text full payload plus preview, only copy; hidden during session; operation none restores only current instance, accepted closes/logs drop accepted without field verification or text |
| Enter veto (shared with 009) | Single contract: 006's `RecoveryDisposition { Pending, Insert, Recover, Cancelled }` changed only by `DestinationManager::set_disposition`; 010 implements `RecoveryPort::before_insertion(&DestinationContext) -> PreInsertionVerdict { Insert, Recover(RecoveryReason) }`, called synchronously by 006 in the first accepted `DispatchGuard::check()` after `paste_delay_ms` (main thread for main-thread methods), with one 50 ms AX deadline, per-element `AXUIElementSetMessagingTimeout` on the destination's application element and every element obtained from it (never the system-wide element, never 0) and `Insert` on doubt, timeout or focus owned by another process; after an `Insert` verdict 006's `recheck()` runs again before `set_disposition(Insert)`; a `Recover(NoTextField)` verdict reaches 010 as the typed reason `no_text_field` (see No-text-field reason); 010 publishes no other veto; 006 sets `Recover` for that verdict, destination failures and `not_read`/`permission_missing`/`uncertain`/`insertion_failed`; 009 consumes its token only on `Insert` under its atomic claim; only `inserted_verified`/`read_observed`/`typed` allow 009 policy, `clipboard_handed_over` allows neither recovery nor Enter; Copy/drag never auto-submit |
| History | saved/not_saved/failed carried from 006, from the actual save_entry result only, never the WAV (a WAV failure saves a text-only row: saved); kept-in-history explanation only saved, no deletion or new durable guarantee |
| 006 reason presenter | `OutcomeConsumer::consume`, called synchronously by `delivery::publish` on the async task of `delivery::deliver`: copy the transcript through `transcript_ref`, admit (`Presenting`), post the presentation to the main thread and return at once `ConsumerAck::PresentationPending(receipt)` (oneshot). `Delivery::Delivered { presentation }` hands the receipt to `insert_final_text`, which awaits it with `tokio::time::timeout(PRESENTATION_GUARD = 2 s)`. `Presented` (first render of that bubble) or `Superseded` (new dictation): no `paste-error`. Confirmed `Unpresentable` (recovery window absent and not creatable, or a creation/show error): `paste-error` as delivered, once, before or after the guard (`delivery::emit_paste_error`). Guard expiry: no `paste-error`, no cancellation, the bubble stays scheduled. 006's slot is released by 010 only after `Presented`, `Superseded` or `Unpresentable`; 010 holds the full copy from the start, so no text is lost. The 300 ms of the spec is a QE target measured from `consume` to `Presented` and reported, never a cutoff. The bubble also replaces the indicator's 006 destination notice. Passive display ≥4 s and indefinite (no timeout), closed earlier only by Copy, Close, accepted drop or a new dictation |
| Platforms | Gate open: macOS full bubble; Windows unavailable/activation/method failure without drag; Linux (session with the `FrontmostAtEnd` route) only method failure without drag; the recovery projection carries no drag action off macOS. Gate closed: `paste-error` everywhere. Native proof: macOS required; Windows/Linux native observations pending release evidence (constitution), their automated suite run on the Linux CI job |
| Settings | `show_recovery_bubble_without_text_field`. Gate closed: absent (`not_found`/4 as in `dev`, absent from `get-all`, no toggle); `AppSettings` keeps the field compiled as `Option<bool>` but normalization sets it to `None`, the descriptor row and `OUTPUT_KEYS` entry are under `cfg(feature = "destination-return")`, and `raw_merge` preserves a value stored by an open build. Gate open: `AppSettings` field exposed in `bindings.ts`, normalized in memory without a write to the stored boolean or `true` on macOS and to `false` on Windows and Linux; `descriptor_data.rs` row, `OUTPUT_KEYS` entry and `PublicSettings` option always filled, so `get`, `output get` and `get-all` return a boolean on every platform; `KEY_CAPABILITIES` row with `PlatformCapability::FocusedFieldDetection` (macOS with the gate open only), so Windows and Linux writes are refused `validation_failed`/2 with `details.reason = "unsupported_platform"`; toggle only on macOS (`useOsType`), UI write through `tauri_adapter::write`; frozen at dictation start, no current-bubble dismiss on mutation |
| Method configuration | 007 adds paste_method=smart_paste to the 008 output descriptor and domain, refused outside macOS with `validation_failed` and `details.reason = "unsupported_platform"` (D4); macOS reliable paste migration owned by 007, Windows reliable paste and Linux methods kept; no clipboard_recovery_* key |
| Settings commands | handy settings output get KEY / output set KEY true\|false --json and generic get/set; same validation/service/revision renderer as 008 |
| JSON/exits | Exactly {ok:true,revision:N,data:{...}} or {ok:false,error:{code,message,details:{...}}}; 0 success, 1 persistence/internal, 2 usage/validation, 3 revision conflict, 4 not found, 5 unavailable; no transcript output |

All UI/native command inputs are typed and identity-validated. Exported preview never becomes drag or Copy source. Recovery state is volatile; crash/restart survival relies solely on successful existing history save. This is a planned contract, not observed runtime proof.
