Choices and limits:

- The plan's `stage`/`preview`/`commit`/`read-page` operations are implemented as `stage-begin`, `stage-append`, `import <mode> <token>` and `read-page`. Pages are pinned by comparing envelope revisions (a moved revision restarts the read, three attempts) rather than server-side snapshots; staging holds the raw import text (at most 1 MiB per input, 32 MiB per process, five seconds) rather than a candidate set.
- Single-rule changes and imports answer with a bounded report (`{rule, position, count}`, `{removed, count}`, import counts and line statuses) instead of the whole committed set, so no reply can exceed one message; `list` gives the set. The id of a rule added by a dry run is provisional.
- `remove` does not revalidate the remaining set, so a set damaged by a manual store edit stays repairable one removal at a time; such a set disables replacement at dictation time (sanitized warning), as before.
- The stage harness is an in-crate test (`dictation_output_tests.rs`) because the settings and transcription modules are private to the library; `tests/replacement_pipeline.rs` keeps the capture/stop harness.
