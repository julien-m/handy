## Follow-ups

- **W1 (delivery review, AC-007).** Replacements run before filler removal and normalization, so a replacement containing a filler or a repeated word can still be changed afterwards (frozen by `downstream_filler_removal_may_still_drop_a_replacement`). Next spec revision: qualify AC-007 (replacement text stays subject to later filler removal and normalization) or protect replaced spans from those steps too. Spec and plan unchanged in this round.
- **W2 (delivery review, constitution native evidence).** The plan's Resolved Test Commands name no Windows or Linux command. Next plan revision: add the 008 `cargo check`/`cargo test` commands for `x86_64-pc-windows-msvc` and `x86_64-unknown-linux-gnu` to Resolved Test Commands and Step 7; they stay pending release evidence (see progress).
- **AC-002 wording.** The orchestrator decision of 2026-10-14 (refuse C0/C1 controls, DEL and bidi embedding, override and isolate controls in both fields) is implemented and documented in the README; record it in AC-002 and the Clarify ledger at the next spec revision, with the ZWJ/ZWNJ CJK-side decision already pending.
- **Collections without a bound (008).** `custom_words`, `custom_filler_words` and `post_process_prompts` have no size bound in the settings service; a routed `get` that would exceed 1 MiB because of them now answers `limit_exceeded` (`reply_too_large`) instead of losing the reply. Paging them belongs to their own domains (vocabulary 003, prompts).
- **Invisible format characters (audit round 2, to decide in the spec).** Both fields still accept U+200B (zero width space), U+2060–U+2064, U+FEFF inside a text, U+206A–U+206F, U+FFF9–U+FFFB and the tag characters U+E0000–U+E007F, which can hide text sent to AI post-processing; tags also build emoji subdivision flags. Decide in AC-002 whether to refuse them (and how to keep flag sequences), and whether `list` text output escapes control characters of a hand-edited store.
- **`debug` log of the settings (audit).** `settings.rs` logs `Loaded settings: {:?}` at `debug`, which includes the rules (allowed by the NFR); consider redacting `word_replacements` from that log.
- **`.gitattributes` (audit).** `unicode-data.txt` has no `.gitattributes` entry; a Windows checkout with `core.autocrlf` could change its bytes. Add `-text` (or `eol=lf`) for it.
- **W1 and W2** above stay open for the next spec and plan revisions; round 2 did not change them.
