## Differences from the plan

- `claim_enter` is also `Stale` once the manager's generation moved on (a cancellation after publication), so a late Windows reliable claim honors a cancellation (review r8 warning); a live session's cancellation still reports `Disposition(Cancelled)`.
- The `ReceiptSink` signals of the reliable paste are defined by the Enter authority (`automatic_enter::rendezvous`) and re-exported to `paste_tx`; `try_reliable_paste` takes `(auto_submit, key)` as one argument.
- `automatic_enter` is read leniently (an invalid value is absent, then `never`), and a closed build drops it from its in-memory settings without writing, so the UI shows `AutoSubmit` there (review r8 warning on the closed build reading an open store).
- No policy+key batch command: the UI changes them with two separate selectors, each one write.
- Story 5's "listing never, always and pin_only": the refusal keeps `validation_failed` with `canonical_value`, its fixed message lists the three values.
- Salvage does not probe `auto_submit` in the open build: without a descriptor it is never written, so its raw value survives anyway.
- `src/bindings.ts` is generated from one `specta_builder()` with a drift test (`bindings_tests`), identical in both gate states.
- UI versus mockup (after the delivery review, round 1): "Pin <destination>" is above the application list (spec Behavioral AC), "Unpin <app>" at the bottom after a divider and the other applications show "This dictation only" while one is pinned, as in the mockup and the contract. `MenuEntry.pinned` marks the pinned application for that hint.
- Test IDs derived by the implementation, to add to the Penflow contract (`penflow/flow-ui-contract/contract.json`, screen `recording-indicator-pinned`) before certification: `recording-indicator-pinned-menu-pin` (Pin entry), `recording-indicator-pinned-destination-mark` (pin mark of the badge), `recording-indicator-pinned-menu-hint` ("This dictation only"). Contract-owned IDs used as is: `recording-indicator-pinned-menu-unpin` and the `output-settings-enter-options-auto-enter*` IDs.
- Delivery review round 1 (`.reviews/delivery.json`): an application chosen in the badge is always activated, even with return off while pinned (orchestrator decision; 006's rule for a badge choice and 009 AC-002), with the focus check before Enter; the key press checks the destination (PID and identity) again on the main thread immediately before the key and is refused past 100 ms (`automatic_enter::key_press`), its reported outcome being the actual one; the `output get` help names `automatic_enter` instead of `auto_submit` with the gate open (unchanged closed); the oversized test files, `errors.rs`, `commit_start`, `PublicGeneral::from_settings` and `AutomaticEnter` were split.
- Inert in the closed build: the IPC commands `pin_destination`, `unpin_destination` and `change_automatic_enter_setting` and the binding types (`automatic_enter`, `source`, `pin`, `MenuEntry.pinned`) exist there but do nothing (no session: `stale`; no descriptor: `not_found`; the snapshot never carries `automatic_enter`).
- Remaining risk recorded by the review and the audit (no change): 007 publishes "read observed" at the first read and the reliable rendezvous fires at the first qualifying read, so a Chromium probe-then-read target may get Enter before the real paste; the native Chromium check stays mandatory before opening the gate, with the remedy (wait for the read quiet period before t0) to plan if it fails.
- The reliable paste's read and injection signalling is one shared helper of `paste_tx` (`record_read`, `inject`), used by the macOS and Windows transactions.
- The command list lives in the `handy_commands!` macro, used by the short `specta_builder()` that both the app's Specta export and the bindings drift test call; the conventions baseline is unchanged from `09cc1ea2` (`livespec conventions verify --feature repo`: PASS, `new_count` 0).
- Three existing test lints of `dev` (engine supervisor, GGUF metadata, portable marker) were fixed so `cargo clippy --all-targets -D warnings` passes.
