# Destination Local Contract — v1

Inspect [the plan](../plan.md) for ownership. Inspect [the spec](../spec.md) for behavior. This artifact defines local Rust/Tauri DTO boundaries, not HTTP endpoints.

| Boundary | Input | Output / invariant |
|---|---|---|
| destination snapshot | active dictation ID | dictation_id, destination_generation, selection_version, phase, support, selection, badge metadata; no text |
| destination menu | current dictation_id/selection_version | opaque entry tokens, foreground-first non-Handy entry, deduplicated windowed apps, FrontmostAtEnd; no window titles |
| choose destination | dictation_id, expected selection_version, opaque token or FrontmostAtEnd | updated snapshot/version before Inserting; stale/closed/frozen request refuses unchanged |
| remove destination cross | exact dictation_id/selection_version, phase before insertion | same FrontmostAtEnd mutation as menu; one click, ≤200 ms badge update, localized Remove destination label; no menu open, keyboard focus or persistent setting change; late/frozen click refused |
| activation | frozen application identity, destination_generation, monotonic deadline | app_closed, activation_failed or dispatch permission; never launch/retry/fallback |
| pre-dispatch guard | frozen resolved identity and generation | `DispatchGuard::check()` immediately after configured delay, before first key/text/script; reads the foreground live (`WorkspacePort::frontmost_now`, macOS Accessibility focused application, never the run-loop-cached `NSWorkspace` value); unreadable foreground with a target fails closed (`activation_failed`); fail means zero new dispatch; the first accepted check builds the `DestinationContext`, sets the disposition `Insert`, and later checks (fallback paths) recheck cancellation and foreground only |
| insertion method | `InsertionPort::dispatch(&self, guard: Arc<DispatchGuard>) -> MethodResult`; the adapter holds the final text and the method settings snapshot read once per insertion (`AppSettings`, also used for the activation route) | the method calls `guard.check()` before each first effect and gets the `DestinationContext` from it; result awaited off the main thread; 007 returns its terminal `PasteOutcome` |
| pre-insertion check (010) | `DestinationContext` | `PreInsertionVerdict { Insert, Recover(RecoveryReason) }` with `RecoveryReason::NoTextField` (wire `no_text_field`, 010 spec "No text field is focused"; 010 extends the enum); absent consumer = `Insert` |
| disposition | dictation_id, destination_generation, next `RecoveryDisposition` | monotonic `Pending → Insert/Recover/Cancelled`, `Insert → Recover/Cancelled`; stale or backward request refused unchanged |
| Enter claim (009) | `DestinationManager::claim_enter(dictation_id, destination_generation)` | under the session lock of `set_disposition`: `EnterClaim` once when the disposition is `Insert`; otherwise `EnterRefusal::{Stale, Disposition(current), AlreadyClaimed}`; never changes the disposition; a later `Recover` does not revoke a granted claim |
| settings get | output key return_to_dictation_app | same 008 success envelope/revision and plain boolean value, like every output key; runtime readability is not reported by the CLI |
| settings set | bool, expected revision when supplied | 008 shared commit; unsupported platform→validation_failed/2 with `details.reason = "unsupported_platform"` and `details.field = "return_to_dictation_app"` (offline and routed, `true` and `false`), invalid→validation_failed/2 (`canonical_type`), stale→revision_conflict/3 |
| recovery access | outcome/dictation opaque transcript_ref | retained final text for trusted native consumer while current; expired reference explicitly unavailable |

Deviation recorded in the delivery review fix round (2026-10-14): the plan text gave the insertion method `dispatch(&DestinationContext, &FinalText, &MethodSnapshot)`. The delivered shape passes the shared guard instead, because the context only exists once the guard accepted the foreground after the method's own delay, and a method with a fallback (reliable paste, 007's AX-then-clipboard chain) must recheck before each effect; the text and the method snapshot belong to the method adapter. 007 adapts to this shape.

`DestinationContext {dictation_id, destination_generation, source, target: Option<ResolvedTarget {pid, identity}>}`: for a captured or badge-chosen application, `target` is the activated instance re-read at the guard; for `FrontmostAtEnd` (return off, unsupported, no destination or chosen at the end) it is the application frontmost at the guard, or `None` when the foreground is unreadable or is Handy; with `None`, 007 skips direct AX insertion. `ApplicationIdentity::{BundleId, Aumid, ExecutablePath}`, `bundle_id()` for 007.

`RecoveryDisposition {Pending, Insert, Recover, Cancelled}` is the single per-dictation insert-or-recover decision and the only Enter veto: 009 claims its Enter token only through `DestinationManager::claim_enter`, which reads `Insert` and records the claim under the same session lock; 010 contributes only through the pre-insertion check above and the failed-result mapping.

`InsertionOutcome` fields: dictation_id, destination_generation, outcome_id (dedup key), transaction_id optional (007), target optional stable identity, destination_source, status, method_outcome optional, reason optional, history_status, history_entry_id optional, transcript_ref optional, completed_at. Status: insertion_attempted/failed/clipboard_handed_over/skipped/cancelled. Reason: app_closed/activation_failed/insertion_failed; 009 adds pinned_app_not_running (pinned application not running; a running pinned application not brought forward within the deadline is activation_failed). History: saved/not_saved/failed from the actual save_entry result, never from the WAV (a WAV failure saves a text-only row: saved). No verified field flag and no public plaintext event.

007 produces the smart-paste method result after destination activation. `method_outcome` carries 007's `PasteOutcome.kind` wire value: `inserted_verified`, `read_observed`, `not_read`, `permission_missing`, `uncertain`, `typed`, `clipboard_handed_over` or `insertion_failed`. `inserted_verified`/`read_observed`/`typed` map to insertion_attempted (disposition stays Insert) while preserving exact method evidence; 006 claims no field verification of its own. `not_read`/`permission_missing`/`uncertain`/`insertion_failed` map to failed with insertion_failed reason and disposition Recover; `clipboard_handed_over` maps to clipboard_handed_over, without Enter or failure recovery from that result alone; 007 alone displays its remote-screen clipboard message. If no method ran or a legacy method has no detailed result, method_outcome is absent. Await 007's direct read-back/clipboard decision outcome off the main thread; enqueue success is not that terminal result.

Producer: terminal destination orchestration in actions.rs; consumers: 009 Enter policy, 010 reason/recovery bubble. For smart paste, only inserted, verified/read observed/typed permit 009 Enter; 010 receives not read/permission missing/uncertain/insertion failed and destination failures with the retained reference. 007 owns pasteboard snapshot/publication/read timing/restoration; 010 Copy changes pasteboard changeCount so 007 abandons pending restoration, with no recovery-window API in 006. Registration is optional; missing feature never prevents terminal outcome. Native registry stores transcript separately from UI event DTO. dictation_id/selection_version/destination_generation reject late/duplicate delivery. Reason presenter capability and acknowledgement transfer display ownership to 010; preserve minimum ≥4 s visibility and visible-overlay fallback if no ack. Style-none before 010 has no bubble; no certified reason presentation claimed then.

007 adds paste_method=smart_paste to the same 008 output-domain descriptor and transaction service, refused outside macOS with validation_failed/2; 006 only adds return_to_dictation_app. Windows reliable paste remains unchanged. No clipboard recovery duration setting is introduced.

Platform refusals (D4) are decided by the shared validator through Step 0's `PlatformCapabilities::check`/`SettingsError::unsupported_platform`, never `unavailable`. Configuration envelope is exactly `{ok:true,revision:N,data:{...}}` or `{ok:false,error:{code,message,details:{...}}}`, newline once on stdout under --json, diagnostics on stderr. Existing 008 exit mapping remains 0 success, 1 persistence/internal, 2 usage/validation/conflict/limit, 3 revision conflict, 4 not found, 5 unavailable (busy, starting, older, store unusable, or a live operation without a running Handy). Optional `details.reason` and `details.items` come from Step 0 (D3). No alternative lock, writer or transport. Pure reads/no-op preserve revision; failed validation/capability/CAS leaves disk unchanged.

007 alone owns the AX-first chain, its read-back verification, fallback decision, clipboard publication, read/no-read timing and restoration (007 AC-009/011/017/018). 006 runs no clipboard timer or restoration and never inserts twice; newer changeCount, including 010 Copy, abandons 007's restoration. Consumer guards in 009 still apply to every eligible result.
