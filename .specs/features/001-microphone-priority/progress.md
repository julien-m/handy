## Notes

### Step 1

- Every open waits at most `OPEN_ATTEMPT_TIMEOUT` (2 s, AC-003). A timed-out worker is abandoned, never joined; if its native open completes later, `AttemptWorker::publish` refuses and the worker drops the stream itself. `OpenLedger` counts abandoned workers still running; at `MAX_STALLED_OPENS` (4) a new open is refused with an error, never a successful capture.
- Loss: the consumer reports a stream error once per stream through `with_loss_callback`; Stop no longer waits the 2 s pause acknowledgement of a dead stream; the processed recording buffer is shared so `stop()` returns the processed prefix even if the consumer thread died.
- Native evidence not produced: the macOS proof (`bun scripts/microphone-native-proof.ts --platform macos --out <dir> [--binary <abs>] [--interactive]`) must run outside the agent sandbox, by an operator, with microphone permission. It blocks `Implemented` (constitution), not the next implementation steps of this run.

### Step 2

- `microphone_priority: Vec<String>` (descriptor `Array`, owner `microphones`, effect `AudioInput`); `selected_microphone` is read-only with no runtime effect and stays stored for a downgrade. Migration only while the key is absent: null → `[]`, any name (`"default"` included) → `[name]`; persisted once by the instance's startup normalization, never by a headless read.
- Generic `set` of either key: `validation_failed`, `details.field`, `details.reason = "microphones_domain"`. Names: unique, non-blank, exact bytes; refusals carry `details.items` (`microphone_name_empty`, `microphone_name_duplicate`), never the name.
- Review r3 warning 1 (intermediate state): from this step the legacy selector keeps working without writing the read-only key. `set_selected_microphone` commits `microphones::priority::selector_change` through `tauri_adapter::write_change` (the chosen device moves first, the other choices stay; the system default empties the list); the store shows the first choice; the audio effect moved to `microphone_priority` and `managers::audio` opens the first choice (or the default) exactly as it opened the legacy selection, without the fallback repair that used to erase the choice. Step 4 replaces this single-choice opening by the ordered resolver; Step 5 replaces the bridge command by the typed priority command.

### Step 3

- `policy::resolve` over `ResolutionPorts` (lid probe, enumeration, open, monotonic clock): closed lid **and** configured override → override then default; otherwise the saved order then default. One fresh catalog per resolution, re-enumerated once after a failure; missing, ambiguous, unresolved and deadline-skipped choices are failed attempts without an open call.
- Budget, checked on the fake clock: each started attempt gets its full 2 s; a configured attempt starts only while ≥ 4 s remain; probes end by t = 4 s (lid probe capped at 1 s) and the default starts by t = 4 s. With two slow devices the trace is `open A@0`, `open B@2000`, `open <default>@4000` (review r3, info 4: two full configured attempts at most, the oracle follows the start rule).
- `catalog::availability`: available, unavailable, ambiguous, unknown; a failed or partial enumeration never proves absence. `native`: enumeration and lid probe on bounded workers, at most 4 running at once.

### Step 4

- Every stream opening (recording start, always-on launch, reopen) runs `policy::resolve` on native ports (`audio_priority::NativePorts`: bounded enumeration and lid probe, `AudioRecorder::open_within`). The device cache and its retry are gone: each opening uses a fresh catalog, so a reconnected higher choice is found. Logs carry timings and attempt kinds only, never device names.
- Effective input (`microphones::effective`): set from the opened stream (name read from the handle, reason, capture generation); a recording copies it as the last recording; idle openings never overwrite it.
- Recording start on an open stream (always-on or warm lazy close): `close_stream_if_not_preferred` checks the preference on a fresh catalog (no open) and closes the stream when another input is now preferred, so the start reopens on it before capture.
- Priority change (live effect of `microphone_priority`): queued on a worker, never blocking the commit (the routed CLI keeps its 5 s answer window); under the state lock it is deferred while a recording runs and applied at its end (`after_recording`). Decisions in `microphones::boundary` (tested exhaustively in `microphone_sessions.rs`).
- Loss: the recorder's loss callback hands off to a worker (the capture thread never waits on a manager lock); during a recording the coordinator gets `InputLost`, which runs the normal stop once (prefix transcribed, no splice, no extra trailing buffer), the UI gets `recording-error` `input_lost` (translated warning toast) and the held key's release is a no-op. Review r3 warning 2: an always-on stream lost during a recording is reopened once at its end; an idle loss is recovered once until the next user action re-arms it.
- Not done here: native proof of the glue on macOS (unplug, reconnect, always-on switch, clamshell) — Step 7.

### Step 5

- `handy settings microphones list` is a D2 live operation (`MicrophonesList`): configured order from `LiveContext::read`, a fresh enumeration bounded to 3 s (inside the 5 s routed answer window) and the effective input from the audio manager. Offline it is the 008 live-only refusal (`unavailable`, 5, `{}`); a routed instance without an audio manager also answers `unavailable` (tested). The real answer needs the running app: native evidence pending.
- `set-priority` is a pure `DomainPlan::Change` (offline `commit_edit_with_probe`, routed `sequence::write_change` with the queued live effect), with `--dry-run`, `--expected-revision`, zero names, `--` for hyphen-leading names. Wire contract: [contracts/microphones-cli.md](contracts/microphones-cli.md).
- Typed UI commands: `set_microphone_priority(order, expected_revision) -> revision` (same `priority_change` through `tauri_adapter::write_change`) and `get_microphone_status() -> MicrophoneStatus` (same projection as `list`). `bindings.ts` is updated by hand (the specta export runs only in a debug app launch); a later debug launch regenerates it.
- Review r3 warning 1 closed: the legacy commands are gone; until the editor ships, the single selector computes the promoted order in the store (`promotedOrder`) and saves it with `setMicrophonePriority` and the window's revision (compare-and-set), never the read-only key.
