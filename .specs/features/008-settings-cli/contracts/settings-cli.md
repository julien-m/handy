# Settings CLI wire contract

This contract is executable for `get`, `keys` and `set` since Step 5 (offline and routed to a running instance) and for the domain framework and the `output` domain since Step 6.

Inspect [the functional source](../spec.md) and [typed protocol](../../../../src-tauri/src/settings_service/protocol.rs). Generate [the JSON schema](settings-cli.schema.json) from `contract_schema()`; its finite metadata comes from the explicit descriptor inventory, not a raw store object. This is JSON Schema, not OpenAPI.

| Operation | Public contract |
| --- | --- |
| `settings get [KEY]` | All known fields (67 in this build: 001 adds `microphone_priority`, 002 `word_replacements`, 007 `smart_paste_migration_version`) or one recognized field; API keys become provider `{present: bool}` entries |
| `settings keys` | Key, canonical value type, nullable flag, allowed values/range, read-only/secret flags, owner and runtime effect category |
| `settings set KEY VALUE` | One scalar value validated by descriptor; list fields name their owner command, readonly/secret fields direct the user to settings UI |
| `settings set ... --expected-revision N` | Refused with `revision_conflict` (`details.current_revision`) unless the settings are at revision N |
| `settings output get [KEY]` | The 11 output settings (`paste_method`, `clipboard_handling`, `auto_submit`, `auto_submit_key`, `paste_delay_ms`, `paste_delay_after_ms`, `reliable_paste`, `typing_tool`, `external_script_path`, `append_trailing_space`, and 006's `return_to_dictation_app`: default `true` on macOS and Windows, `false` elsewhere; a set of `true` or `false` on a build without the destination capability is `validation_failed`, exit 2, `details.reason = "unsupported_platform"`) or one of them; another key is `not_found` |
| `settings output set KEY VALUE [--expected-revision N] [--dry-run]` | Same descriptor validation and commit path as `set`; `--dry-run` returns `{"dry_run":true,"changes":{KEY:value}}` at the current revision, writes nothing and runs no live effect; an invalid dry run is `validation_failed` (exit 2) with no preview |
| `settings vocabulary list` / `export -` (003) | `{terms:[{index,term,issue}],count}` with every stored occurrence unchanged (`issue` names why it is not sent: `empty`, `too_long`, `line_break`, `forbidden_character`, `duplicate`, `over_capacity`, or null); `export -` gives one stored term per line (`data.content`), another target is `usage_error` |
| `settings vocabulary add TERM` / `remove TERM` / `import FILE\|- [--mode merge\|replace]` (003) | One atomic `custom_words` change with `--expected-revision` and `--dry-run`; a refused term or line is `validation_failed` with `details.items` (`term_empty`, `term_too_long`, `term_line_break`, `term_forbidden_character`, `term_duplicate`), the 501st term `limit_exceeded`, an absent term `not_found` |
| `settings vocabulary status` (003) | Live operation: `{model_id,mode,status,reason,mechanism,budget,terms_sent,terms_not_sent,evidence_kind}` for the selected model; offline `unavailable` (exit 5, empty details); undocumented budget `internal_error` with `details.reason = "context_budget_unverified"` |
| `settings microphones list` / `settings microphones set-priority [NAME]... [--expected-revision N] [--dry-run]` | Feature 001, see [its contract](../../001-microphone-priority/contracts/microphones-cli.md): `list` is a live operation (offline: `unavailable`, exit 5, empty details); `set-priority` commits the complete order offline or routed, `{"microphone_priority": [...]}` |
| Domains (framework) | `handy settings <domain> <action>`; `--help` lists exactly the domains of the build (`output` only in 008). Wire request `domain` carries `domain`, `action` (aliases `edit`→`update`, `delete`→`remove`), positional `arguments`, `input` (file or `-` stdin content read by the CLI process, UTF-8, at most 1 MiB: larger is `limit_exceeded`, non-UTF-8 is `validation_failed` with `details.offset`; a terminal stdin is refused, never prompted), `dry_run` and `expected_revision`. A domain change commits atomically through the shared path (all or nothing). A live-only answer or a live operation without a running instance is `unavailable` (exit 5, empty details); a live operation (006 Step 0, `DomainPlan::Live`) runs only inside the instance reached through the private channel, never in the CLI process, and writes settings only through the instance's ordered write. Export to `-` prints only the exchange content without `--json` and puts it in `data.content` with it |

The scalar CLI grammar accepts exact booleans `true`/`false`, unsigned integers, finite bounded numbers, canonical enum strings and literal strings. Nullable fields accept exact `null` to clear. Whitespace in meaningful strings is preserved. For the device selectors (`clamshell_microphone`, `selected_output_device`), `null` is the only representation of the system default on every surface (the UI sends null for its "Default" entry); every string, `default` included (a real ALSA PCM name on Linux), is a device name stored byte for byte. Since 001 the normal microphone choices are the ordered list `microphone_priority` (the empty list is the system default), changed only through the microphones domain: generic `set` of `microphone_priority` or of the legacy `selected_microphone` (now read-only, kept stored for a downgrade) is `validation_failed`, exit 2, `details.reason = "microphones_domain"`. Disk-only log-level integers/uppercase and overlay-position `none` aliases are rejected as mutation input. Prompt selection requires current membership. Build policy may disable updater mutation. Widget step increments are not imposed.

Both pure validation ports use fixed English categories/reasons; the existing Tauri writers are migrated in Step 4. Numeric/channel native availability and prepared runtime effects are checked by their later owning adapters.

Success is `{"ok":true,"revision":N,"data":…}`. Failure is `{"ok":false,"error":{"code":C,"message":M,"details":{…}}}`. Details always remain an object; recognized fields/issues, current revision, an outcome (`unknown` after a timeout or unconfirmed durability, `committed` when a live effect failed after a durable write), and, since 006 Step 0, an optional closed `reason` (`unsupported_platform`: `validation_failed`, exit 2, decided by the shared validator offline and routed alike; 004 adds `shortcut_session_busy`, `instance_required`, `last_shortcut`, `alternatives_unsupported`, `registration_refused` and `invalid_shortcut`, with the allowlisted shortcut details `action_id`, `owning_action`, `owning_shortcut`, `kind` and `limit`; 003 adds the vocabulary term codes `term_empty`, `term_too_long`, `term_line_break`, `term_forbidden_character` and `term_duplicate`, used as `items[].code` of a `validation_failed` refusal, and `context_budget_unverified`, an `internal_error`, exit 1; 001 adds `microphones_domain`, and the item codes `microphone_name_empty` and `microphone_name_duplicate`) and optional `items` (at most 100 refused input positions `{index, code, message}`, sorted by index, never a candidate value) are the only admitted details; both new fields are absent unless a refusal sets them. Unknown key/candidate/parser text never enters errors. Revision is an unsigned 64-bit integer independent of settings schema version.

| Category | Exit |
| --- | --- |
| `usage_error`, `validation_failed`, `shortcut_conflict`, `limit_exceeded` | 2 |
| `revision_conflict` | 3 |
| `not_found` | 4 |
| `unavailable` | 5 (also: the operation needs a running Handy) |
| `persistence_failed`, `internal_error` | 1 |
| Success | 0 |

Owned categories are usage, validation, revision conflict, not found, unavailable, persistence failure and internal error. Shortcut conflict and limit exceeded retain the documented extension mapping; no current domain-handler behavior is certified by their DTO definitions.

Request DTOs carry protocol version, request/store identity and a typed get/keys/set/domain operation. Over the private channel (Unix socket in a per-user 0700 directory, Windows logon-SID pipe), both ends authenticate the peer before any byte, frames are 4-byte length-prefixed and bounded to 1 MiB, and the CLI waits at most 5 s: no answer, a broken stream or a reply to another request is `unavailable` with `details.outcome = "unknown"`; read again before retrying. With `--json`, stdout holds exactly one envelope line; diagnostics, warnings and recovery hints go to stderr. No network listener or MCP server is introduced.
