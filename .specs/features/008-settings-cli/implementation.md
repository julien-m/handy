### Step 3 audit dispositions

Source: [final Step 3 audit](proofs/current-run-step3/audit-final.stdout). RED/GREEN evidence: [RED](proofs/claude-step3/red-audit-findings.stdout), [temp RED note](proofs/claude-step3/red-temp-retry.note.txt), [GREEN](proofs/claude-step3/cargo-test.stdout).

| Finding | Severity | Disposition |
| --- | --- | --- |
| transaction.rs:34 parent ABA substitution | blocker | Fixed (detection). The parent (dev, ino) is recorded right after the transaction lock and the (dev, ino) of the store file actually read is kept; both are rechecked immediately before replacement (`verify_origin`), and any mismatch returns `persistence_failed` with nothing written. Test `substitution::parent_substituted_before_read_and_restored_before_replace_is_refused` uses the new `PersistStage::AfterLoad` injection point. Operations were not rewritten with `openat`/`renameat` (orchestrator decision, minimal scope). A same-user attacker renaming the directory during a transaction is outside the spec's threat model: this is detection, not prevention; a rename that also restores the exact store inode is not detected. Windows pins the parent with handles that deny rename for the lock lifetime. |
| locator.rs:62 symlink aliases accepted | major | Fixed. `reject_aliases` walks every existing component with `symlink_metadata` before canonicalizing and refuses any symlink (`unavailable`) except root-owned Unix system links such as macOS `/var` → `/private/var`; Windows symlinks and junctions are always refused. Tests: `store_file_symlink_is_refused_for_reads_and_writes`, `ancestor_directory_symlink_is_refused_by_locator_and_repository`. |
| atomic.rs:112 temp name reuse after PID reuse | major | Fixed. `private_temp_with` skips names that already exist (left untouched) for at most 64 attempts, then fails closed with `persistence_failed`. Unit tests in `atomic.rs`. |
| transaction.rs:195 array merge without unique ids | major | Fixed in [raw_merge.rs](../../../src-tauri/src/settings_service/raw_merge.rs). Unknown item fields are preserved only when typed and stored items all carry unique non-null `id`s; otherwise the typed array replaces the stored one (unknown item fields dropped, never copied onto another item). Test `startup_merge_never_copies_unknown_fields_between_items_with_duplicate_ids`. |
| settings.rs:822 `ensure_post_process_defaults` docs | minor | Fixed (doc comment: inserted/synchronized defaults, mutation, return value). |
| settings.rs:1123 `apply_settings_migrations` docs | minor | Fixed (doc comment: raw payload dependency, in-place migrations, return value). |
| store.rs:31 `read_snapshot` side effects | minor | Fixed (docs state that reads never create the parent or store but may create and retain `settings.lock` in an existing parent). |
| atomic.rs:30 `persist` too long | minor | Fixed. `persist` is now the orchestration sequence; `ParentDirectory` (open/validate/replace/sync) and `confirm_durable` hold the parts. |
| transaction.rs:26 `commit_with_probe` too long | minor | Fixed. Split into `lock_and_load`, `apply_mutation` and `persist_locked`. |
| transaction.rs:72 `initialize` too long | minor | Fixed. Uses `lock_and_load`, `normalize_document` and `persist_locked`. |
| windows_store.rs:74 `pin_directory` too long | minor | Not fixed. Windows-only native handle code that cannot run on the macOS host (compile-only check); refactoring security-critical FFI without executing its tests adds risk for a style-only gain.
